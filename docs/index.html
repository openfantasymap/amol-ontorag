amol-ontorag

Ars Magica, as an OntoRAG GitHub-as-storage dataset.

A reusable repository that a retrieval service reads to answer questions, grounded in an ontology (knowledge graph), content (chunked, entity-linked text), and embeddings — all derived from the Ars Magica Open License corpus. The git repository is the database.

The contract

A consumer reads manifest.json and follows the paths it declares. Everything is plain text / NDJSON / Turtle — diffable and host-agnostic.

ontology/world.ttl — RDF knowledge graph
ontology/entities.jsonl — flat entity index
content/chunks/*.jsonl — text, one file per book, entity-linked
embeddings/vectors/*.jsonl — vectors, joined by id
content/books.json — the pack registry (dc:requires)
schema/*.schema.json — the record contracts

Ontology & provenance

Entities (Characters, Spells, Houses, Tribunals, Covenants, Creatures, concepts…) were LLM-extracted from the prose and aligned to a TTRPG schema. Each entity records where it comes from: attestedIn (books whose prose mentions it) and definedIn (books it was extracted from) — the footprint and the origin of every fact.

Composition — add or remove packs

Each sourcebook is a semantic pack. Packs form a dc:requires dependency graph (every supplement requires the core rules). Selecting packs and closing over their dependencies reconstructs a scoped world — the basis for access-scoping and per-source evaluation.

python3 tools/compose.py --packs covenants    # dc:requires pulls in the core rules
python3 tools/compose.py --validate           # integrity + soundness of the dataset

Query it

Point the generic OntoRAG MCP server at this repo — it reads the dataset over GitHub and serves graph-aware retrieval (vector / ontology / hybrid):

ONTORAG_DEFAULT_REPO=openfantasymap/amol-ontorag \
ONTORAG_RETRIEVAL=ontology docker compose up server
